# Feature: MEMORY-V0-2026-05-13 — Activate SQLite v0 Memory + Consult System

**Purpose**: Plan skeleton for the MEMORY-V0 mission — activate JANUS's memory architecture on SQLite v0. Four scientist agents converged on a resilience score of 22/100. This mission creates context seed files, moves entity tools to active directory, backfills error log, wires consult points into the orchestrator, wires write-back into mission completion, and auto-refreshes world_env.json.

## Key Decisions
- **SQLite v0 as storage backend** — deliberate simplification; swappable to neural when LCN Brain passes Phase C validation. Entity schema: Decision, Rejection, Error, Pattern, Convention. No ORM, inline ULID generation.
- **Idempotent upserts** — natural_key (computed from entity content) + entity_type unique index prevents duplicate rows. `write_entity` does SELECT-first, UPDATE-or-INSERT.
- **Consult gated by environment** — all 3 consult points (pre_plan, pre_dispatch, post_verify) gate on `JANUS_CONSULT_DISABLED` environment variable or file existence check on `consult.py`. Graceful degradation if tools missing.
- **Entity store path**: `.lcn/lcn.sqlite` — separate from GUI's `agent_memory.db` and OpenCode's own DB. Keeps memory subsystem self-contained and swappable.

## Boundaries

| Module | What goes in | What stays out |
|--------|-------------|---------------|
| `lcn_write.py` | Entity validation, idempotent write, connection management | Read queries, consult logic, CLI orchestration |
| `lcn_read.py` | Read queries only (5 query types) | Write operations, validation, CLI argparsing |
| `consult.py` | Orchestrator helper — 3 structured query modes | Raw DB access, entity validation, write logic |
| `capability_assessor.py` | Tier classification only | Entity storage, session state, dispatch logic |

## Edge Cases

| Scenario | Handling |
|----------|---------|
| `consult.py` not found | All consult steps skip silently. Orchestrator continues without querying entity store |
| `lcn_write.py` fails on write-back | Log error to `error-log.jsonl` via `error_logger.py log`. Do NOT block mission completion |
| Entity store `.lcn/lcn.sqlite` doesn't exist | Auto-created by `get_conn()` (parent dirs + schema init on first connect) |
| Entity validation fails | `ValidationError` raised; caller catches, logs, skips that entity; batch continues with others |
| `JANUS_CONSULT_DISABLED` env var set | All consult steps skip. Orchestrator doesn't even check for consult.py existence |
| Multiple concurrent orchestrator writes | SQLite handles concurrent writes via WAL (implicit — single connection per write). Risk of `database is locked` on heavy concurrency; acceptable for ~dozens/mission volume |
| Entity natural key collision | Idempotent upsert — existing row updated (preserving `created_at`, refreshing `updated_at`) |
| world_env.py scan fails | Orchestrator logs and continues with stale world_env.json. Not a blocking failure |
| Error-log.jsonl backfill duplicates | Script checks existing entries before inserting; skip if same `(error_type, context)` pair exists |

## Constraints

- **No new dependencies** — all tools use stdlib only (sqlite3, json, hashlib, pathlib, re). No pip installs
- **No deletion of reference code** — `MagnumOpus/reference/lcn_write.py` and `MagnumOpus/reference/capability_assessor.py` stay as spec code after move
- **Graceful degradation** — all consult and write-back paths must fail gracefully. Never block a mission or session start because the entity store is unavailable
- **Env-var gating** — `JANUS_CONSULT_DISABLED` must skip all consult steps. `JANUS_CONSULT_DISABLED` takes priority over file existence checks
- **Global-agent sync** — orchestrator.md changes must be dual-written to `~/.config/opencode/agents/orchestrator.md`
- **Global-skill sync** — mission-completion SKILL.md changes must be dual-written to `~/.config/opencode/skills/mission-completion/SKILL.md`
- **Not forking consult** — consult queries are synchronous (subprocess, 30s timeout). No parallel consult queries in this version
